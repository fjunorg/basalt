# Basalt 产品需求说明书（基于 v1.7.0 实现逆推）

> 本文档从产品视角描述 Basalt 的功能需求，供社区理解产品边界与演进依据。
> 逆推原则：**以代码实况为准、零夸大**——部分覆盖项如实标注实现范围；已拍板的战略决策如实记录为需求边界。
> 配套阅读：[introduction.md](introduction.md)（门面文档）、[CHANGELOG](../CHANGELOG.md)（版本明细）。

## 1. 产品目标与用户角色

### 1.1 产品目标

为 ToB/ToG 交付团队提供一个**开箱即用、合规内建、AI 原生**的后端平台底座：团队在其上二次开发业务系统时，身份/租户/审批/审计/通知/调度等平台能力与 AI 治理能力（网关/配额/内容安全/RAG/Agent）已就位，且以单二进制交付适配私有化与信创环境。

### 1.2 用户角色

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| 平台管理员 | 运营管理台的日常使用者 | 用户/角色/菜单/租户/套餐/字典/参数/错误码/通知的全生命周期管理 |
| 业务用户 | 审批人、财务/公文/合同操作者 | 待办处理（会签/依次/加签/驳回）、单据流转、通知触达 |
| 运维工程师 | 部署与排障 | 单二进制/容器部署、日志与指标、等保自查、审计链校验、备份恢复 |
| 二次开发者 | 基于平台构建业务模块的工程师 | 模块化扩展（Registry/RFC 流程）、OpenAPI、代码契约、存储接口缝 |

## 2. 功能需求（按模块）

> 每模块含：需求描述 / 核心用例 / 验收要点 / 当前实现范围（含边界如实标注）。

### 2.1 L0 内核（kernel）

- **需求**：模块化运行时——模块经 Registry 依赖拓扑排序装配（Init/Start 正序、Stop 逆序）；HTTP 路由抽象（模块零 gin 依赖）；配置（环境变量）；结构化日志；OTel 可观测（无端点 no-op）；国密 Provider（SM3 摘要 + SM2 签名，GB/T 官方向量验证）；数据权限 Scope 纯模型；CLI。
- **用例**：新模块 5 分钟脚手架接入（`basalt new module`）；无 OTel 端点时零开销运行。
- **验收**：模块拓扑排序正确性、国密向量全过、观测 no-op 不阻塞。
- **实现范围**：全部交付；CLI 含 serve/version/new/seed/secure。

### 2.2 identity（身份与权限 v0.3）

- **需求**：用户/角色 RBAC（权限点通配匹配）；OAuth2 2.1 授权服务器（授权码+PKCE、客户端凭证、轮换刷新+重放吊链）；SSO 应用管理；三方登录（钉钉实装、企微预留）；角色数据权限五档（all/dept/dept_and_below/self/custom，多角色并集取宽、解析失败 fail-closed）；会话管理（注册表、踢下线 kicked_at 机制、JWT jti）。
- **用例**：钉钉扫码登录并自动注册；按「本部门及以下」查看用户列表；管理员踢出异常会话即时生效。
- **验收**：PKCE 正反用例、重放检测、五档数据裁剪矩阵、踢下线立即生效。
- **实现范围**：全部交付；**企微三方登录为预留接口缝**。

### 2.3 tenant / tenantpkg（多租户 v0.2 / 租户套餐 v0.1）

- **需求**：租户 CRUD 与上下文实时解析；行级隔离；dedicated-db 库级隔离（14 业务模块请求级路由、DSN 环境变量注入不落库、绝不静默回退、首访懒建库）；租户套餐（菜单/权限模板、绑定计数、在用禁删、PermFilter 单点裁剪）。
- **用例**：创建 dedicated 租户绑定 gov-db 引用，该租户用户登录后业务读写自动落专属库；绑定「基础套餐」后菜单与权限点即时收敛。
- **验收**：三库物理隔离实证、切换隔离模式不支持在线变更（受控迁移）、套餐裁剪 E2E。
- **实现范围**：交付如上；**shared-db 模式经评估不实现**（需求边界，见 §4）；平台级模块（identity/tenant/audit/quota/aisafety/tenantpkg/errcode）固定主库。

### 2.4 audit（防篡改审计 v0.2）

- **需求**：全平台关键事件入链式哈希审计链（登录/业务/AI 调用/notify 发送）；链尾 SM2 签名防整库重算；篡改精确定位；算法切换（SHA-256↔SM3）后多算法逐段核验；GORM 持久化重启续链；签名/验签 HTTP 端点（audit:sign 权限与读分离）。
- **用例**：安全审计员触发链校验并获得「完整/断链位置」结论；启用链签名后验证历史签名有效性（不依赖当前私钥）。
- **验收**：篡改单条/删除条目/伪造签名分别被 SigOK/ChainOK 检出。
- **实现范围**：全部交付；签名默认 off（BASALT_SM2_CHAIN_SIGN=on 启用）。

### 2.5 workflow（轻量审批流 v0.2）

- **需求**：流程定义与实例管理；审批动作全集：通过/驳回/撤回/会签/或签/**依次审批/抄送/转办/委派/加签（前/后）/驳回至已过节点（轮次机制）**；待办与已办；守卫（403/409）；多步直发。
- **用例**：报销单按「部门经理会签 → 财务或签」流转；审批人临时加签外部专家；对已过节点驳回重审（旧轮动作失效、历史保留）。
- **验收**：状态机三实现（Mem/GORM/Routed）语义一致；轮次/委派计票按名义审批人。
- **实现范围**：高频审批子集交付；**BPMN 设计器与表单引擎为非目标**（轻量定位，见 §4）。

### 2.6 org / dict / sysconfig / errcode / menu（组织与配置 v0.1）

- **需求**：部门树+岗位（树级数据权限裁剪）；数据字典（类型+数据项）；运行期参数 KV；错误码注册表（含种子）；动态菜单（CRUD/角色绑定/按权限过滤下发、空下发前端回退静态、种子三分组幂等、管理页防死锁）。
- **用例**：受限角色登录仅见被授权菜单组；字典项供表单下拉统一维护。
- **验收**：菜单过滤矩阵（无权剪子树/目录失子则剪/无 perm 叶保留/禁用全剪）。
- **实现范围**：全部交付。

### 2.7 notice / notify（公告与通知 v0.1）

- **需求**：notice 全员公告（草稿/发布/已读）；notify 通知中心——短信/邮件/站内信三渠道、模板渲染（未匹配变量保留排障）、凭据环境变量注入、发送日志（手动重发语义）、站内信收件箱（定向到人）。
- **用例**：审批通过触发邮件+站内信双渠道通知；短信渠道凭据轮换无需重启改库。
- **验收**：渲染矩阵、阿里云短信签名齐备性、失败明确不静默重试。
- **实现范围**：阿里云短信/SMTP 实装；**腾讯云短信为预留缝**（TC3 随真机矩阵）。

### 2.8 file / job（文件与调度 v0.1）

- **需求**：file 本地上传下载 + **S3 兼容多云驱动**（自研 SigV4、path/virtual-host 双风格、混合存量路由、预签名直链）；job 调度（间隔+cron 双模式、在线动态 HTTP 任务 job:manage、执行日志分页、重启恢复含 NextRun 重算）。
- **用例**：切换 MinIO 后旧本地文件仍可访问可删除；注册每工作日 9 点的 HTTP 回调任务。
- **验收**：SigV4 官方向量对齐、cron 触发矩阵（跨月/跨年/工作日）、动态任务生命周期。
- **实现范围**：交付如上；**非 S3 协议对象存储（如七牛原生）为预留缝**；file 字节流默认共享磁盘（元数据已隔离）。

### 2.9 finance / document / contract（业务三件 v0.1）

- **需求**：财务（报销/付款/发票登记/部门预算，提交即审批联动+预算预检+通过占用+付款闭环）；公文（收发文/密级缓急/审批联动/归档）；合同（登记/审批/生效完结/到期扫描入审计链督办）。三者均接入数据权限（finance 部门+申请人双维、document 拟稿部门）。
- **用例**：报销单预算预检拒绝超额；合同临期 30 天自动记入审计链供督办。
- **验收**：审批联动状态一致、预算占用原子、数据权限裁剪矩阵。
- **实现范围**：核心闭环交付（对标自研 ToB/ToG 高频域，非完整 FMS/OA 全家桶）。

### 2.10 oplog（操作与 API 日志 v0.1）

- **需求**：audit 链之外的日常排障查询面：异步采集（不阻塞请求、满丢弃计数）、用户字段完整验签、采样（all/write/off）、日志分页过滤、90 秒滑动窗口 QPS/错误率。
- **用例**：按状态码 5xx 过滤最近一小时错误请求定位故障。
- **验收**：非阻塞采集、Stop 优雅排空、环形窗口指标。
- **实现范围**：交付如上；默认内存滚动（10000 条），PERSIST=sqlite 可落库。

### 2.11 ai-gateway / ai-safety（AI 网关与内容安全 v0.2 / v0.1）

- **需求**：OpenAI 兼容统一层（vLLM/Ollama/Qwen/GLM/DeepSeek 等）；SSE 流式（include_usage 注入记账）；租户月度账期 Token 配额（跨期延续、原子记账、429 封锁）；调用审计入链；内容安全（敏感词库、租户策略回落、reject/replace/mark、输入输出双侧含 SSE 跨 chunk）。
- **用例**：租户 A 配额耗尽被 429 拦截而租户 B 不受影响；命中敏感词的流式输出按策略断流并下发 error 事件。
- **验收**：配额原子性（并发记账）、断流语义、策略回落链。
- **实现范围**：全部交付（治理层为全市场空白项）。

### 2.12 rag / agent（知识与编排 v0.1）

- **需求**：rag 完整管道（库→文档→切片→向量化→相似检索；OpenAI 兼容 embeddings、sqlite blob 向量起步、VectorSearcher 预留专用库、文档双通道）；agent 轻量编排（定义→运行→工具循环→SSE 七类事件；LLM 一律经网关；内置 RAG 检索工具；ToolRegistry 预留生态）。
- **用例**：上传公司制度文档建立知识库；Agent 定义「制度问答助手」绑定 RAG 工具，运行时流式返回带检索依据的回答；内容安全命中落 safety_rejected 终态。
- **验收**：重启后检索可用（blob 落库）、工具调用成对事件、未配置 embedding 明确报错。
- **实现范围**：交付如上；**rag 无 Console 页面（API-only）**；深度文档解析（RAGFlow 级）非目标；不集成 Eino（自研轻量循环，接口缝预留）。

### 2.13 console（管理台 v0.1）

- **需求**：32 视图全功能管理台；动态菜单（后端下发+静态回退）；按钮级权限（can()）；SSE 全事件消费（AI 对话/Agent 运行）；Semi Design 视觉；go:embed 单二进制。
- **用例**：受限角色登录仅见授权页面，直达 URL 落 403 引导页。
- **验收**：菜单/守卫一致性、TS strict 构建链零错误。
- **实现范围**：交付如上；暗色模式未提供。

## 4. 明确的非目标（战略边界，已决策）

1. **支付系统不自研**（v1.6.0 战略决策记录）：B 端收款走生态集成。
2. **垂直业务域生态承接**：商城/CRM/ERP/WMS/CMS/MES/HRM/PMS/IoT 等不自研，以插件机制承接（docs/03 v0.1 决策，竞品 Gap 报告复核维持）。
3. **shared-db 租户模式不实现**（tenant-isolation.md §4 评估结论：sqlite 无对应物/需求已被行级+dedicated 覆盖）。
4. **BPMN 设计器与表单引擎不做**（工作流轻量定位；复杂编排建议外接 Flowable 类引擎）。
5. **SM4/GMTLS 待接**（gmsm 生态就绪，随密钥管理体系演进）；postgres/openGauss 驱动接线 pending（占位分支显式报错）。
