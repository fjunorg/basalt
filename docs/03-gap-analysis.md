# 03 · 竞品差距分析（Gap Analysis）

> 对标对象：**芋道 yudao**（平台业务层基线）× **Spring AI**（AI 框架基线）× **Eino**（Go AI 编排基线）
> 视角：本框架（Basalt）要进入的是三者交集 + Go 生态空白处
> 关联文档：`01-architecture.md`、`02-oss-governance.md`
> 版本：v0.1 · 2026-10-27

---

## 1. 竞品能力基线速览

| | 芋道 yudao | Spring AI | Eino |
|---|---|---|---|
| **定位** | Java 企业级全功能平台 | Java 框架的 AI 抽象层 | Go 的 LLM 应用编排框架 |
| **平台业务**（RBAC/租户/工作流/审计） | ✅ 全有（工作流基于 Flowable） | ❌ | ❌ |
| **AI 能力** | 点缀（会员版 AI 对话模块） | ✅ 模型抽象/Embedding/RAG/Tool/评估/记忆 | ✅ Chain/Graph 编排/组件抽象/流式/ADK |
| **多租户 AI 治理**（配额/成本/审计） | ❌ | ❌ | ❌ |
| **国密/等保/信创** | ❌（项目级定制） | ❌ | ❌ |
| **语言** | Java | Java | Go |
| **授权** | MIT + 付费增值服务 | Apache 2.0 纯开源 | Apache 2.0 纯开源 |
| **用户规模** | GitHub ~30k star | Spring 生态数百万开发者背书 | 字节内部生产 + 社区早期 |

**结论**：三者交集处（平台级 × AI 原生 × 纯开源 × Go）完全空缺；且三者都缺「ToG 合规开箱化」。

## 2. 平台业务层差距（对标芋道）

| 能力项 | 芋道 | Basalt 规划 | 差距评估 | 优先级 | 里程碑 |
|--------|------|------------|---------|--------|--------|
| RBAC 用户/角色/菜单权限 | ✅ | mod-identity | 成熟方案可对齐（casbin 已被 go-admin 验证） | **P0** | M1 |
| 数据权限（部门级数据隔离） | ✅ | mod-identity（数据权限 DSL） | 需自研 DSL，中等工作量 | **P0** | M2 |
| 多租户 SaaS | ✅（行级） | mod-tenant（**独立库/共享/行级三模式**） | 超越点：芋道仅行级；三模式是 B 端大客户刚需 | **P0** | M1 |

| 操作审计日志 | ✅ 基础 | mod-audit + **SM3 链式防篡改 + 等保留存策略** | 超越点：审计可信度（G 端测评实际检查项） | **P0** | M2 |

| 文件服务 | ✅ | mod-file | 常规对齐，需加国产对象存储驱动 | P1 | M2 |
| 数据字典/行政区划 | ✅ | mod-dict | 直接对齐 | P2 | M3 |
| 代码生成器 | ✅ | mod-codegen（OpenAPI 契约驱动） | 对齐 goctl 水平即可 | P1 | M2 |
| 商城/CRM/ERP/支付 | ✅（大而全卖点） | ❌ **明确不做** | 战略取舍：垂直业务模块留给生态插件市场，防芋道式复杂度失控 | — | — |
| 流程表单设计器 | ✅（商用版更强） | M3 评估（低代码方向） | 视社区需求再立项 | P2 | M3 |

## 3. AI 基础设施层差距（对标 Spring AI × Eino）

| 能力项 | Spring AI | Eino | Basalt 规划 | 差距评估 | 优先级 | 里程碑 |
|--------|-----------|------|------------|---------|--------|--------|
| 模型接入抽象（多 Provider） | ✅ ChatModel | ✅ Model 组件 | ai-gateway：**OpenAI 兼容协议统一层**（Qwen/GLM/DeepSeek/vLLM/Ollama 一套通吃） | 策略差异：不做每家私有 SDK，只走兼容协议 + 私有化端点；私有能力走适配器接口 | **P0** | M2 |
| 流式输出 | ✅ | ✅（强项：流式处理） | 复用 Eino | 零差距（集成即得） | P0 | M3 |
| Embedding/向量化 | ✅ | ✅ 组件 | 复用 Eino + 国产模型端点 | 零差距 | P1 | M3 |
| 向量库抽象 | ✅ VectorStore（十余种） | ✅ Indexer/Retriever | **pgvector 为默认**，接口可插拔 | 差距：Spring AI 的 VectorStore 生态广度短期追不上；但 pgvector 单选更聚焦（且信创 PG 系兼容是超越点） | P1 | M3 |
| RAG 管道 | ✅ ETL + Advisor | ✅ 组件化 | ai-rag 管道编排 | 对齐即可；深度文档解析（RAGFlow 级）明确不做，留可插拔口 | P1 | M3 |
| Tool/Function Calling | ✅ | ✅ Tool 组件 | 复用 Eino | 零差距 | P0 | M3 |

| Prompt 模板与版本管理 | ✅ 基础 | ⚠️ 弱 | ai-prompt（版本/AB/审批流） | 超越点：Prompt 变更纳入平台审批工作流（G 端 AI 上线的合规刚需） | **P0** | M3 |
| 评估（evaluation） | ✅ Evaluator | ❌ | ai-prompt 评估集回归（**中文评估基准**） | 超越点：竞品无一内置中文评估集 | P1 | M3 |
| 结构化输出 | ✅ | ✅ | 复用双方 | 零差距 | P1 | M3 |
| Chat Memory | ✅ | ✅ | 复用 + 多租户隔离存储 | 需自研租户隔离封装 | P1 | M3 |
| 可观测（AI 调用 trace） | ✅ Micrometer | ✅ Callbacks | otel 集成 + **AI 专用 span**（成本/token 维度） | 超越点：token 成本进入租户账单维度 | P1 | M3 |
| **多租户 Token 配额/限速** | ❌ | ❌ | ai-quota | **全市场空白**，G/B 端采购硬指标 | **P0** | M2 |
| **AI 成本核算归集** | ❌ | ❌ | ai-gateway 成本账单（租户/应用/模型维度） | 全市场空白 | **P0** | M2 |
| **内容安全（输入输出过滤）** | ❌ | ❌ | ai-safety（敏感词引擎 + 可插拔三方审核 + 模型自审） | **全市场空白**；生成式 AI 管理办法 + 等保的合规刚需 | **P0** | M3 |
| **AI 全链路审计** | ❌ | ❌ | ai-safety → mod-audit（谁、何时、什么 Prompt、什么输出、过审与否） | 全市场空白；G 端 AI 项目验收检查项 | **P0** | M3 |
| 国产私有化模型开箱 | 部分（社区） | 部分 | 一等公民（vLLM/Ollama/Qwen/GLM/DeepSeek 端点模板） | 差异化：私有化部署文档与模板最全 | **P0** | M2 |

## 4. 合规与信创差距（无对标——纯增量战场）

| 能力项 | 竞品现状 | Basalt 规划 | 优先级 |
|--------|---------|------------|--------|
| 国密 SM2/SM3/SM4（传输/存储/签名） | 全部缺失 | kernel-crypto 全栈 + GMTLS 双证书默认模板 | **P0** |
| 等保三级参考配置（安装即合规基线） | 全部缺失 | SECURITY 基线 + 自动化自查命令 `basalt secure --check` | **P0** |
| 审计日志防篡改与留存策略 | 全部缺失 | mod-audit 链式哈希 | **P0** |
| 信创 OS/CPU 矩阵（麒麟/统信 × 鲲鹏/龙芯） | 全部缺失 | CI 交叉编译矩阵 + 兼容性认证指南 | P1 |
| 国产数据库（达梦/openGauss/OceanBase） | 部分框架社区讨论级 | GORM 方言层 + CI 真机矩阵 | P1 |
| SBOM/签名/可复现构建 | Spring 生态有 | release 流程内建 | P1 |

> 这一节是唯一"无对标物"的能力域——意味着没有可抄的作业，也意味着**做了就是第一**。G 端招投标中"支持国密算法、支持国产数据库"是常见硬性参数，目前所有 Go 框架都只能靠项目定制应付。

## 5. 汇总：P0 清单与差距性质标注

| P0 能力 | 性质 |
|---------|------|
| 多租户（三模式）、RBAC、数据权限 | 追平（芋道已定义水位线） |
| 轻量审批工作流 | 追平 + 高风险自研（Go 生态短板） |
| 模型网关（OpenAI 兼容统一层 + 私有化模板） | 追平 Spring AI/Eino + 私有化超越 |
| Token 配额/成本核算/AI 审计/内容安全 | **空白抢占（无竞品）** |
| 国密/等保基线/防篡改审计 | **空白抢占（无竞品）** |
| Prompt 治理 + 审批流联动 | 空白抢占 |

**战略结论**：追平项保证"可用性"（对齐 Java 竞品水位），空白抢占项构成"必买/必选理由"。资源分配建议：M1 全力追平平台基础；M2 起把差异化火力集中在「AI 治理四件套（配额/成本/审计/安全）+ 国密合规」——这两组能力同时命中 2026 年 G/B 端 AI 采购的验收清单，且 12 个月窗口内没有竞品有迹象补齐。
