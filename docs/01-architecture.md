# 01 · 框架模块架构设计

> 项目：**纯 Go**、纯开源、AI 原生、面向 ToB/ToG 的通用后端平台框架
> 代号：**Basalt（玄武岩）** —— 占位代号，正式名称待定
> 版本：v0.2（架构修订：技术栈收敛为纯 Go，Ruby L3 层移除，改为前端控制台层）· 2026-10-27
> 关联文档：`02-oss-governance.md`（开源治理）、`03-gap-analysis.md`（竞品差距分析）、`04-frontend-ui-evaluation.md`（前端选型）

## 1. 设计原则（决定架构的五个不可妥协项）

| # | 原则 | 含义 | 源自竞品调研的教训 |
|---|------|------|-------------------|
| P1 | **纯 Go，单二进制交付** | 后端全部能力由 Go 承担；前端构建产物 go:embed 嵌入，交付物是一个可执行文件 | 双语言架构（如原 Ruby 方案）在国内 ToG 场景生态为零，招标即出局；收敛后交付与运维复杂度大幅下降 |
| P2 | **AI 是一级公民** | 模型网关、配额、审计进入内核而非外挂模块；不装 AI 模块时框架完全可独立运行 | Spring AI 已证明此路线，Go 生态无人占位 |
| P3 | **合规内建，默认开启** | 国密、审计日志、数据权限是默认行为而非配置选项 | 无任何 Go 竞品做到；Java 侧靠项目级定制 |
| P4 | **模块可插拔、可裁剪** | 单体可裁剪（学 Rails 引擎理念），微服务可拆分（学 go-zero）；模块间只走显式接口 | 芋道"功能大而全"导致复杂度失控的反面教训 |
| P5 | **纯开源，零功能差异** | 框架所有功能只有一份代码一份协议；商业化只卖服务，不卖功能 | 与 JeecgBoot（开源版阉割 30%）、BladeX（闭源）划清界限 |

## 2. 分层架构总览

```
┌──────────────────────────────────────────────────────────────────┐
│  L3 前端控制台层（Vue 3 + Element Plus，go:embed 嵌入二进制）       │
│  Admin Console · 登录/布局/权限路由 · 用户·租户·审计·AI 控制台页面  │
│  （构建产物嵌入；后端模块通过路由协议动态下发菜单/权限点）            │
├──────────────────────────────────────────────────────────────────┤
│  L2 AI 基础设施层（Go）                       【差异化核心】       │
│  ┌────────────┬────────────┬────────────┬────────────┐           │
│  │ Model      │ RAG        │ Agent      │ AI 治理     │           │
│  │ Gateway    │ Pipeline   │ Runtime    │ 配额·审计   │           │
│  └────────────┴────────────┴────────────┴────────────┘           │
├──────────────────────────────────────────────────────────────────┤
│  L1 平台业务层（Go modules，全部可插拔）      【对标芋道】         │
│  身份/RBAC · 多租户 · 工作流 · 审计 · 文件 · 通知 · 字典 · 代码生成│
├──────────────────────────────────────────────────────────────────┤
│  L0 内核运行时层（Go）                        【对标 go-zero】    │
│  HTTP/gRPC · 配置 · 日志/可观测 · 服务治理 · 国密 TLS · CLI        │
├──────────────────────────────────────────────────────────────────┤
│  横切面：信创适配（麒麟OS/龙芯/鲲鹏 · 达梦/openGauss/OceanBase）  │
│          部署（K8s · docker-compose · 信创裸机）· 安全基线         │
└──────────────────────────────────────────────────────────────────┘
```

**依赖规则**：只能向下依赖，同层模块间必须通过接口（interface）通信；
L3 只能通过 L0/L1 暴露的 OpenAPI 访问后端，构建产物经 go:embed 嵌入 Go 二进制。

## 3. 各层模块明细

### L0 · 内核运行时层（Go）

| 模块 | 职责 | 技术选型 | 对标/参照 |
|------|------|---------|----------|
| `kernel-web` | HTTP 服务、中间件链、OpenAPI 文档生成 | gin（生态最大）+ oapi-codegen（契约先行） | gin-vue-admin |
| `kernel-rpc` | gRPC 服务、服务间调用 | grpc-go | Kratos |
| `kernel-config` | 多源配置、热更新、密钥管理 | koanf/viper + 本地加密存储 | Spring Environment |
| `kernel-observability` | 结构化日志、metrics、trace 三件套 | **slog（标准库，零依赖，信创友好）** + OpenTelemetry | otel 生态 |
| `kernel-governance` | 限流、熔断、注册发现、负载均衡 | sentinel-go + 注册中心抽象（**nacos 优先**，etcd/consul 可换） | go-zero / sentinel |
| `kernel-crypto` | 国密 SM2/SM3/SM4、GMTLS 双证书、密码哈希 | **emmansun/gmsm**（活跃、支持 GMTLS 1.3） | 无竞品（空白） |
| `kernel-cli` | 脚手架、模块装卸、迁移、文档生成、**数据工厂（seed，承接原 seedlab 职责）** | cobra | goctl、rails new |

> 关键决策：日志选 slog 而非 zap——信创环境最小依赖原则；国密进 L0 而非 L1，因为 TLS/传输加密是运行时能力。

### L1 · 平台业务层（Go，全部可插拔）

| 模块 | 职责 | 技术选型 | 对标 | 风险 |
|------|------|---------|------|------|
| `mod-identity` | 用户/组织/角色/RBAC/数据权限/SSO(OAuth2+OIDC) | casbin + 自研数据权限 DSL | 芋道、go-admin | 低 |
| `mod-tenant` | SaaS 多租户（独立库/共享库/行级三种模式） | GORM 插件实现租户上下文注入 | 芋道（仅行级） | 中 |
| `mod-workflow` | 人工审批流（发起/审批/会签/委托/撤回）+ BPMN 子集 | **自研轻量审批引擎**；复杂流程通过 sidecar 委托 Flowable（Java 进程，可选） | 芋道(Flowable)、JeecgBoot | **高（Go 生态无成熟 BPMN 引擎，为最大自研坑）** |
| `mod-audit` | 全操作审计日志、防篡改链式哈希（SM3 签名）、留存策略 | 自研 + 事件总线 | 无竞品做到链式防篡改 | 中 |
| `mod-notify` | 短信/邮件/站内信/webhook 统一通知 | 渠道抽象（含阿里云/腾讯云） | 芋道 | 低 |
| `mod-file` | 文件存储抽象（MinIO/本地/国产对象存储） | S3 协议 + 驱动接口 | 芋道 | 低 |
| `mod-dict` | 数据字典、枚举管理、地区数据 | 常规 | 若依 | 低 |
| `mod-codegen` | CRUD 代码生成（表→API→前端） | 基于 OpenAPI 契约模板 | goctl、gin-vue-admin | 中 |

> 多租户是 B 端 SaaS 与 G 端"一套系统多委办局"的共同底座，列为 L1 最高优先模块。

### L2 · AI 基础设施层（Go）——差异化核心

| 模块 | 职责 | 技术选型 | 对标 | 差异化点 |
|------|------|---------|------|---------|
| `ai-gateway` | 统一模型接入（OpenAI 兼容协议一网打尽 Qwen/GLM/DeepSeek/vLLM/Ollama 私有化）、路由、故障转移、成本归集到租户 | 自研网关 + OpenAI 协议适配层 | Spring AI ChatModel | **多租户级成本核算无竞品** |
| `ai-quota` | 租户/用户级 Token 配额、限速、计费账单 | tiktoken-go + Redis/DB 计数器 | 无竞品 | G 端采购硬指标 |
| `ai-rag` | 文档解析→分块→向量化→检索管道，可插拔向量库 | **Eino 组件** + pgvector（信创 PG 系兼容）默认驱动 | Spring AI VectorStore、RAGFlow | RAGFlow 级深度解析不做，走可插拔 |
| `ai-agent` | Agent 编排（工具调用、多步规划、记忆） | **Eino ADK/Graph**（不重造轮子） | Eino、LangGraph | 平台化封装（租户隔离的 Agent 市场） |
| `ai-safety` | 输入/输出内容安全（敏感词、涉政过滤、可插拔三方审核）、**AI 调用全链路审计** | 自研钩子 + 事件总线对接 mod-audit | **无竞品**（最大空白） | 等保 + 生成式 AI 管理办法合规 |
| `ai-prompt` | Prompt 版本管理、A/B、评估集回归 | 自研 | Spring AI 评估器 | 中文场景评估集 |

> 关键决策：**AI 编排不自研**。Eino（Apache 2.0，字节生产验证）作为 L2 的编排底座，自研聚焦在它没有的部分：网关、租户配额、安全审计、Prompt 治理。同时在 `ai-gateway` 内做 Provider 抽象隔离，降低对 Eino 的硬依赖（字节单点风险）。

### L3 · 前端控制台层（Vue 3，构建产物嵌入）——官方 UI，可整体替换

> 详细选型论证见 `04-frontend-ui-evaluation.md`。

| 模块 | 职责 | 说明 |
|------|------|------|
| `console`（Admin Console） | 框架官方管理后台：登录/布局/动态权限路由（菜单与权限点由后端模块经路由协议下发）、用户/租户/审计/AI 控制台页面（约 15–20 页） | Vue 3 + TypeScript + Vite + Element Plus，自研（不 fork 模板） |
| `ui-contract` | 前端 UI 契约：路由/菜单/权限点/组件槽位的声明协议 | 后端模块注册页面 → Console 动态渲染；同时为未来社区版 React Console 预留生态位 |
| 部署形态 | `go:embed` 嵌入 Go 二进制；开发时前后端分离（Vite dev server 代理） | 全部静态资源离线打包（私有化无外网场景），禁用运行时 CDN |

**前端协同规则**（取代原双语言协同铁律）：
1. 前端只通过 OpenAPI 契约与后端交互（oapi-codegen 生成 Go server stub，openapi-generator 生成 TS client）；
2. Console 路由表由后端模块在运行时下发（服务权限控制与模块插拔）；
3. 构建产物必须 embed 进二进制——发布物永远是单个可执行文件 + 数据库驱动清单。

## 4. 部署形态（一套代码，三种交付）

| 形态 | 场景 | 组成 |
|------|------|------|
| **All-in-One 单体** | G 端小项目/私有化盒子 | 单二进制（Go embed 前端）+ SQLite/单库 PG |
| **模块化单体** | B 端 SaaS 主流 | 单进程多模块，按需裁剪 L1/L2 模块 |
| **微服务** | 大型政企 | L1 各模块独立部署，nacos 注册，K8s 编排 |

信创适配为横切能力：麒麟 OS / 统信 UOS（ARM 鲲鹏 + 龙芯 LoongArch 交叉编译矩阵）、达梦/openGauss/OceanBase 数据库驱动（GORM 方言层适配 + CI 真机测试矩阵）。

## 5. 里程碑（对应 12 个月占位窗口）

| 里程碑 | 时间 | 交付 | 验证标准 |
|--------|------|------|---------|
| **M1 内核可用** | 0–3 月 | L0 全部 + mod-identity + mod-tenant + CLI 脚手架 + Apache 2.0 协议挂牌 | 用 CLI 15 分钟起一个带登录+多租户的后端 |
| **M2 平台级 MVP** | 3–6 月 | mod-workflow(轻量审批) + mod-audit + ai-gateway + ai-quota | 一个"带审批流和 AI 配额管控"的完整 demo；信创双一（麒麟+达梦）跑通 |
| **M3 AI 原生完整** | 6–12 月 | ai-rag + ai-agent(Eino 集成) + ai-safety + L3 Admin Console（含 AI 控制台） | 对外 1.0 发布；通过等保三级参考配置清单自查 |

## 6. 架构风险登记册（Top 5）

| 风险 | 等级 | 缓解 |
|------|------|------|
| Go 工作流引擎自研深坑 | 高 | 范围锁定人工审批流（80% G 端场景），BPMN 完整版走 Flowable sidecar 可选集成 |
| Eino 单点依赖（字节主导） | 中 | ai-gateway Provider 抽象 + 熔断降级到直连模式 |
| 达梦/OceanBase 驱动质量参差 | 中 | GORM 方言抽象层 + CI 多库测试矩阵，社区共建驱动 |
| 双语言社区认知成本（"为什么有 Ruby？"） → 已随技术栈收敛消除 | — | — |
| 前端组件库长期维护风险（Element Plus 依赖） | 中 | ui-contract 契约层隔离 UI 实现；组件库可替换（Naive UI/Arco 备选兼容设计） |
| 团队被定制项目掏空（纯开源现金流风险） | 高 | 治理文档（02）中设"核心团队 60% 时间保护条款" |
